\sectiontitle{What you need}
\begin{itemize}
\item Python 3.10+, a new virtual environment, and read-only access to the private \texttt{catyans/reins} repository.
\item One real multi-step task, its existing tests, and a named engineer who can define an accepted result.
\item A customer-local storage path; keep provider keys and raw run data in your environment.
\end{itemize}
\sectiontitle{Install the pilot version}
\texttt{git clone git@github.com:catyans/reins.git /path/to/reins}\\
\texttt{python -m pip install /path/to/reins}

\sectiontitle{1 / See a whole task, not just its model calls}
Wrap one complete business task in \texttt{@trace} and configure Reins once before work starts. Observation records what happens without blocking calls. Let your own business check decide whether the result is usable.

\begin{quote}\ttfamily\small
configure(storage\_path="./pilot.duckdb", mode="observe")\\
@trace(agent\_name="supplier\_agent", task\_type="supplier\_lookup")\\
async def research(source):\\
\hspace*{1em}result = await existing\_agent(source)\\
\hspace*{1em}record\_outcome(success=required\_fields\_pass(result))\\
\hspace*{1em}return result
\end{quote}

Run the original and wrapped task on the same inputs. Compare prompts, outputs and external side effects. Then use \texttt{reins compare --database ./pilot.duckdb --task-type supplier\_lookup}. A process-local timeline is available by setting \texttt{dashboard=True} and opening \texttt{127.0.0.1:8765} while the Agent runs.

\sectiontitle{3 / Decide when to add budget rules}
After reviewing real runs, agree on a task budget, a reliable upper limit for each paid call, allowed models and tools, and what to keep if a task stops. Try \texttt{mode="enforce"} on a small set of \emph{new} tasks. Calls already sent may still be billed.
